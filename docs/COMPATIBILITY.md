# Kompatibilitas WebForge Mobile — v0.5.0

Matriks ini menyatakan status jujur setiap fitur dan runtime di v0.5.0 (`com.webforge.mobile`, Android `minSdk 26` / `targetSdk 35`, ARM64). Bukti perangkat terakhir tetap **Uji Semua Engine** nyata di POCO M6 pada 2026-11-26 (v0.3.1): static, PHP, Caddy, dan Apache lolos; Nginx, Python, Node.js, PostgreSQL, dan MariaDB gagal dengan error persis yang dicatat di matriks runtime. Perbaikan kelima kegagalan itu masuk di v0.3.2, v0.4.0 menambahkan supervisi kesehatan berkelanjutan, probe LAN nyata, mode komposit PHP, tail log file, dan Tes Akses LAN, dan v0.5.0 menambahkan PHP multi-versi (8.2/8.3/8.4) dengan PHP-FPM, Apache+PHP via FPM, Composer, kirim email SMTP, server SFTP, tema visual glassmorphism biru laut dengan brand Faza X TCP, dan ikon launcher baru. Fitur baru v0.5.0 berstatus **Terbuild di CI, menunggu tes perangkat** — belum ada yang diklaim lolos di POCO M6. Status kelima engine yang gagal tetap **Gagal di perangkat** sampai retest di POCO M6 lolos; v0.4.0 dan v0.5.0 sendiri belum terverifikasi di perangkat. Status yang dipakai:

- **Berfungsi** — terimplementasi nyata dan terhubung ke core; perilaku sesuai keterangan.
- **Parsial** — sebagian berfungsi dengan batasan nyata yang dijelaskan; batasan tidak disembunyikan.
- **Terbuild di CI, menunggu tes perangkat** — binary benar-benar ada di APK hasil CI dan terdeteksi core, tetapi health check di POCO M6 belum lolos/terlapor. Status naik menjadi **Berfungsi** hanya setelah tes perangkat.
- **Gagal di perangkat** — self-test/health check di POCO M6 benar-benar gagal; error ringkasnya dicatat apa adanya. Perbaikan yang sudah dibuat tidak menaikkan status sebelum retest perangkat lolos.
- **Belum tersedia — belum dibundel** — tidak ada di APK. Aplikasi menampilkan status ini beserta alasannya dan tidak menyediakan tombol Start. Rencana bundelnya ada di [RUNTIME_PLAN.md](RUNTIME_PLAN.md).

Prinsip yang mengikat seluruh matriks: status server `running` hanya dari health check yang lolos, deteksi runtime hanya dari binary yang benar-benar ada, dan angka monitoring hanya dari `/proc` yang benar-benar terbaca. Tidak ada mock data di jalur produksi.

## Matriks fitur

| Fitur | Status v0.5.0 | Alasan / keterangan |
|---|---|---|
| Static server (Rust) | **Berfungsi** | Terbukti di POCO M6 (self-test 2026-11-26: marker terverifikasi via HTTP GET). Menyajikan file dari document root proyek. Di Android berjalan sebagai task in-process (`in_process: true`, `pid: null`); di host dev sebagai proses anak `webforge-core serve-static`. Start memeriksa konflik port lalu health check ke alamat bind sebenarnya (IP LAN + Host LAN bila `bind_lan`, loopback bila tidak); gagal berarti status `error`, bukan `running`. HTTP 403 pada `/` tidak dianggap sehat penuh: server tetap berjalan hanya dengan peringatan docroot. Bind `127.0.0.1` default, LAN opt-in per server. HTTP saja, port ≥ 1024. |
| Deteksi 17 framework | **Parsial** | Deteksi berbasis file berfungsi untuk 17 pola: Static HTML, Native PHP, Laravel, CodeIgniter 4, Symfony, WordPress, Flask, Django, FastAPI, Express, NestJS, Next.js, Nuxt, Vue, React, Angular, SvelteKit (plus `Unknown` sebagai fallback). Hasilnya mencakup bahasa, runtime yang direkomendasikan, document root yang disarankan, file penanda yang ditemukan, dan `readiness`. Parsial karena deteksi ≠ bisa jalan: proyek PHP/Python/Node terdeteksi dengan benar tetapi proyek tetap `readiness: needs_dependencies` bila dependensinya belum terinstal. Deteksi adalah heuristik file, bukan analisis kode penuh; versi framework hanya dilaporkan bila terbaca dari file penanda. |
| File manager | **Berfungsi** | List, baca (maks. 1 MB; biner ditolak `415`), tulis, mkdir, rename, copy, move, delete, pencarian nama rekursif (maks. 200 hasil), dan ukuran direktori — semua di dalam folder proyek. Path di-canonicalize; traversal keluar proyek ditolak `403`. Code editor (CodeMirror 6) memakai endpoint baca/tulis yang sama. Wilayah kerja adalah workspace aplikasi, bukan seluruh penyimpanan HP. |
| SQLite manager | **Berfungsi** | Database SQLite dibuat di `<data>/databases/<name>.db`; daftar tabel/kolom, query SELECT maupun DML (error SQL dikembalikan apa adanya), backup, dan restore dari folder backup. Ini manajer untuk file SQLite milik aplikasi — bukan server database jaringan. |
| Terminal | **Parsial** | Eksekusi `sh -c` nyata di cwd proyek/workspace, timeout 30 detik, streaming WebSocket, riwayat tersimpan. Parsial karena shell Android sangat terbatas: bukan bash, tidak ada manajer paket sistem; `pip`/`npm` tersedia lewat panel runtime Python/Node (bukan perintah terminal umum), dan binary yang bisa dipanggil hanya yang ada di sistem/`nativeLibraryDir`. |
| Monitoring | **Parsial** | CPU dari delta `/proc/stat` (2 sampel, 200 ms), memori dari `/proc/meminfo`, storage dari statvfs workspace, port LISTEN dari `/proc/net/tcp`+`tcp6` (state `0A`), riwayat tiap 30 detik. Parsial karena bergantung pada keterbacaan `/proc` di perangkat: bila tidak tersedia, nilai `null` + `unavailable_reason`, bukan angka karangan. Sebagian OEM membatasi visibilitas proses aplikasi lain, jadi daftar proses bisa lebih pendek dari kenyataan sistem. |
| Logs | **Berfungsi** | Log aplikasi dan per-server tersimpan di SQLite, bisa difilter severity/pencarian, dan diekspor sebagai teks. Sejak v0.4.0 core men-tail file ErrorLog/CustomLog Apache dan error/access log Nginx ke pusat log per-server, dengan offset per file agar restart tidak menduplikasi baris lama. |
| Supervisi kesehatan | **Berfungsi** | Core mem-probe HTTP setiap server running/degraded tiap 10 detik ke alamat bind sebenarnya (LAN IP + Host LAN bila `bind_lan`). Transisi jujur: running → degraded setelah probe gagal beruntun → restart otomatis maks 3 kali dengan backoff → error berisi bukti probe terakhir. Sejak v0.5.0 respons HTTP 403/404 membuktikan server hidup dan hanya menjadi peringatan docroot, bukan alasan restart; restart hanya untuk kegagalan transport (timeout/koneksi gagal). Semua transisi tercatat di log dan kolom kesehatan server. |
| PHP multi-versi + FPM (Nginx/Caddy/Apache) | **Terbuild di CI, menunggu tes perangkat** | PHP 8.2, 8.3, dan 8.4 dapat dipilih per proyek/server (default: pilihan proyek, lalu rekomendasi framework, lalu pilihan Core); versi yang tidak tersedia ditampilkan nonaktif beserta alasannya. Memilih Nginx/Caddy/Apache untuk proyek PHP tanpa proxy eksplisit menyalakan PHP-FPM internal versi terpilih (`backend_kind: php-fpm`) sehingga `index.php` dieksekusi nyata; Apache meneruskan PHP lewat `mod_proxy_fcgi`. Proxy eksplisit ke backend lain tetap memakai `backend_kind: proxy`. Stop mematikan frontend dan backend. Belum terverifikasi di POCO M6. |
| Composer | **Terbuild di CI, menunggu tes perangkat** | Composer dibundel dan dapat dijalankan per proyek PHP (install, update, require paket) dengan versi PHP terpilih; status `composer.json`/`composer.lock`/`vendor/` dan output nyata (exit code, stdout, stderr, durasi) ditampilkan apa adanya. Composer membutuhkan jaringan internet untuk mengunduh paket; tanpa jaringan perintah gagal dengan error aslinya. Belum terverifikasi di POCO M6. |
| Email (SMTP) | **Terbuild di CI, menunggu tes perangkat** | Pengaturan SMTP (host, port, keamanan none/STARTTLS/TLS, username, password write-only, From) tersimpan di Core dan dipakai shim sendmail agar aplikasi PHP dapat mengirim email; tombol Kirim Email Tes menampilkan hasil/error apa adanya. Pengiriman nyata bergantung pada server SMTP pengguna dan jaringan. Belum terverifikasi di POCO M6. |
| SFTP | **Terbuild di CI, menunggu tes perangkat** | Server SFTP (russh) berakar di workspace aplikasi dengan autentikasi username/password (password tersimpan sebagai hash); bind loopback default, akses LAN opt-in dengan peringatan keamanan. UI menampilkan fingerprint host key, daftar koneksi aktif, dan reset password yang hanya ditampilkan sekali. Belum terverifikasi di POCO M6. |
| Tema visual & branding | **Terbuild di CI, menunggu tes perangkat** | Antarmuka memakai tema glassmorphism biru laut (panel kaca semi-transparan dengan backdrop blur, aksen cyan, latar gelap kebiruan dengan grid/glow halus); tema terang tetap tersedia sebagai glass terang biru laut muda dengan kontras teks yang dijaga. Brand Faza X TCP tampil di header dan bagian Tentang; judul aplikasi tetap WebForge Mobile. Ikon launcher baru (perisai + prompt terminal + node jaringan, biru laut) dipasang sebagai adaptive icon dengan fallback mipmap PNG. Verifikasi visual di POCO M6 belum dilakukan. |
| Tes Akses LAN | **Berfungsi** | Tombol per server running/degraded menjalankan HTTP GET nyata dari core ke IP LAN:port dengan Host LAN dan menampilkan status, durasi, URL, dan error apa adanya. Bila `bind_lan` nonaktif atau IP LAN tidak terdeteksi, hasil tes menyatakan itu secara eksplisit. |
| Diagnostics | **Berfungsi** | `GET /api/system/diagnostics` menjalankan pemeriksaan nyata (runtime terdeteksi, port, storage) dengan status `ok`/`warn`/`error` per pemeriksaan. Sejak v0.3.1 ada **Uji Semua Engine** (`POST /api/diagnostics/self-test`): tiap engine benar-benar di-start di port ephemeral dengan docroot temp, di-GET, lalu di-stop; PostgreSQL/MariaDB diuji dengan instance temp + `SELECT 1`. Sejak v0.4.0 engine HTTP juga diuji lewat jalur LAN (bind `0.0.0.0`, probe ke IP LAN dengan Host LAN) bila IP LAN terdeteksi, dan hasil loopback/LAN ditampilkan terpisah; kegagalan LAN membuat hasil keseluruhan gagal. Panel Log Startup menampilkan kejadian startup core (hasil nativeStart, error library, progres ekstraksi aset, restart watchdog) agar kegagalan bisa dilaporkan dengan bukti. |
| Git status | **Parsial** | `git status --porcelain` nyata **bila** binary git terdeteksi di PATH/`nativeLibraryDir`. Di APK Android Phase 1 git tidak dibundel, jadi umumnya `available: false` dengan alasan. Di host dev yang punya git, fitur ini berfungsi penuh. |
| Background service | **Parsial** | Foreground service dengan notifikasi persisten menjaga core tetap hidup selama sistem mengizinkan; sejak v0.2.0 partial WakeLock dipegang selama ada server aktif (toggle di Pengaturan); sejak v0.4.0 WakeLock tidak dilepas karena satu cek `/api/servers` gagal sesaat — keadaan terakhir yang diketahui dipertahankan selama core/foreground service hidup, dan WakeLock hanya lepas bila cek berhasil membuktikan tidak ada server aktif, toggle mati, service berhenti, atau watchdog menyerah. UI menampilkan banner peringatan bila server aktif tetapi pengecualian baterai belum diberikan, beserta panduan manual Autostart HyperOS (tidak dapat dideteksi API). Watchdog me-restart core yang mati. Parsial karena Android tetap berhak menghentikan proses: optimasi baterai OEM, freezer HyperOS, batas proses latar, dan phantom-process killer (Android 12+) bisa membuat proses server tidak mendapat CPU atau mematikan core beserta servernya. WakeLock tidak mencegah freezer, dan aplikasi tidak dapat memaksa pengecualian dari dalam; mitigasi yang tersedia adalah deteksi (supervisi kesehatan), restart otomatis, dan panduan pengguna. Tidak ada janji uptime. |
| SAF (impor folder) | **Parsial** | Pemilih folder `ACTION_OPEN_DOCUMENT_TREE` berfungsi dan menyalin tree terpilih ke workspace lewat `DocumentFile`, lalu proyek didaftarkan dari salinan itu. Parsial karena modelnya salin-masuk: folder asal tidak diedit langsung, perubahan tidak menulis balik, dan aplikasi tidak meminta `MANAGE_EXTERNAL_STORAGE`. Server membutuhkan path nyata, dan SAF tidak menyediakan path bebas — lihat [ARCHITECTURE.md](ARCHITECTURE.md). |

## Matriks runtime dan layanan

| Runtime / layanan | Status v0.5.0 | Alasan / keterangan |
|---|---|---|
| PHP | **Parsial** | PHP 8.3.14 terbukti di POCO M6 (self-test 2026-11-26: lolos, marker terverifikasi via HTTP GET). Sejak v0.5.0 PHP 8.2, 8.3, dan 8.4 (CLI + FPM) di-cross-compile di CI (NDK, dependensi statis) dan dapat dipilih per proyek/server; multi-versi dan ekstensi tambahan (curl, gd, exif, soap, ftp, pcntl; intl dicoba) berstatus **Terbuild di CI, menunggu tes perangkat** — daftar ekstensi definitif hanya dari `php -m` di perangkat. Engine `php -S`, php.ini terkelola, PHP info per versi, PHP CLI runner, dan Composer terhubung ke binary nyata itu. |
| PHP-FPM | **Terbuild di CI, menunggu tes perangkat** | SAPI FPM dibangun untuk PHP 8.2/8.3/8.4 dan menjadi backend PHP untuk Nginx, Caddy, dan Apache (`backend_kind: php-fpm`); status FPM per versi dilaporkan apa adanya oleh Core. Belum terverifikasi di POCO M6. |
| Apache httpd | **Berfungsi** | Terbukti di POCO M6 (self-test 2026-11-26: Apache 2.4.62 lolos, marker terverifikasi via HTTP GET). httpd 2.4 di-cross-compile statis (APR, APR-util, PCRE2, expat, OpenSSL) sebagai `libhttpd.so`; core men-generate `httpd.conf` + VirtualHost per proyek, validasi `httpd -t` sebelum start. Sejak v0.5.0 `mod_proxy_fcgi` dikompilasi agar Apache menjalankan PHP via PHP-FPM (**Terbuild di CI, menunggu tes perangkat**); reverse proxy umum ke backend lain tetap tidak tersedia di Apache dan mengembalikan error jujur. Sejak v0.4.0 konfigurasi memakai `ScoreBoardFile` eksplisit di server home dan `AcceptFilter http none` (menghindari TCP_DEFER_ACCEPT di Android), tetap mpm_event 1 child dengan validasi `httpd -t` wajib. HTTP saja. |
| Nginx | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `"daemon" directive is duplicate` dan error log compile-time `/webforge/error.log` tidak bisa dibuka. Perbaikan v0.3.2: `daemon off;` hanya di konfigurasi (flag `-g` yang menggandakan dihapus) dan path bawaan Nginx dibuat relatif terhadap prefix runtime. Status naik hanya setelah retest v0.4.0 lolos. HTTP saja (tanpa SSL/HTTP2). |
| Caddy | **Berfungsi** | Terbukti di POCO M6 (self-test 2026-11-26: lolos, marker terverifikasi via HTTP GET). Caddy 2.8.4 di-cross-compile Go (`GOOS=android`, `GOARCH=arm64`, `CGO_ENABLED=0`) sebagai `libcaddy.so`; core men-generate Caddyfile dengan site address catch-all `:port` + `bind` eksplisit agar Host LAN dan loopback sama-sama dilayani (`file_server`, opsi `reverse_proxy`), validasi `caddy validate`. v0.3.2 menanam `CustomVersion=v2.8.4` agar `caddy version` tidak lagi menampilkan hash commit. TLS otomatis/ACME tidak dipakai untuk alamat lokal. |
| Python / Flask / Django / FastAPI | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `ModuleNotFoundError: No module named 'math'` saat import `http.server` (modul ekstensi inti tidak statis dan `lib-dynload` tidak dikemas). Perbaikan v0.3.2: semua modul ekstensi aktif dipaksa statis dan CI gagal keras bila modul kritis (termasuk `math`) tidak terdaftar di binary. Status naik hanya setelah retest v0.4.0 lolos. Framework tetap harus terinstal dari requirements proyek; wheel native Android umumnya tidak tersedia. |
| Node.js / npm | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `dlopen failed: library "libc++_shared.so" not found` untuk `libwebforge_node.so`. Perbaikan v0.3.2: `libc++_shared.so` dari NDK dikemas ke APK dan divalidasi CI. Status naik hanya setelah retest v0.4.0 lolos. Node berjalan di proses `:node` terpisah (stop membunuh proses itu); npm CLI dibundel (`npm.zip`); modul native `.node` umumnya tidak tersedia untuk Android. |
| MariaDB | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: bootstrap `ERROR: 1046 No database selected`. Perbaikan v0.3.2: SQL bootstrap diawali `CREATE DATABASE IF NOT EXISTS mysql; USE mysql;` dan password root dipasang untuk localhost + 127.0.0.1. Status naik hanya setelah retest v0.4.0 lolos. Koneksi MariaDB/MySQL eksternal tetap tersedia (tes koneksi TCP+auth nyata). Lisensi GPLv2 berlaku untuk binary MariaDB. |
| PostgreSQL | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `initdb: error: program "postgres" is needed by initdb but was not found in the same directory as ".../libinitdb.so"` (path executable di-realpath menembus symlink). Perbaikan v0.3.2: patch `normalize_exec_path` PostgreSQL agar lokasi symlink `bin/` dipertahankan, plus symlink basi antar update APK diganti otomatis. Status naik hanya setelah retest v0.4.0 lolos. Shared memory dipaksa `mmap`; tanpa ICU/XML (collation C/POSIX). |
| SSL / ACME (HTTPS) | **Belum tersedia — belum dibundel** | Semua server lokal melayani HTTP saja; Nginx dibangun tanpa modul SSL/HTTP2. Tabel `certificates` ada di skema sebagai registry, tetapi penerbitan/penyajian HTTPS belum diimplementasikan. ACME juga membutuhkan domain publik dan tantangan yang bisa dijangkau internet — tidak realistis dari HP di jaringan lokal tanpa tunnel. |

## Catatan perangkat dan platform

- **Arsitektur:** APK v0.5.0 menargetkan `arm64-v8a`. Perangkat uji utama adalah Xiaomi POCO M6 (ARM64, HyperOS); bukti perangkat terakhir adalah Uji Semua Engine 2026-11-26 pada v0.3.1 (static/PHP/Caddy/Apache lolos; Nginx/Python/Node/PostgreSQL/MariaDB gagal, diperbaiki di v0.3.2, dan menunggu retest v0.4.0 termasuk mode LAN). Laporan pemakaian nyata v0.3.2 menunjukkan Apache/Nginx/Caddy dapat menggantung saat aplikasi di background; v0.4.0 menangani ini dengan supervisi kesehatan, probe LAN, dan restart otomatis, tetapi freezer HyperOS tidak dapat dipaksa dari aplikasi. Perilaku OEM lain — terutama soal pembunuhan proses latar — bisa berbeda dan belum terverifikasi di luar perangkat uji.
- **Versi Android:** `minSdk 26`, `targetSdk 35`. Kebijakan W^X Android 10+ berlaku penuh: kode native hanya dieksekusi dari `nativeLibraryDir`.
- **Port:** hanya port ≥ 1024. Management API tetap di `127.0.0.1:8765` dan tidak bisa diakses dari jaringan.
- **Deteksi di host dev bukan bukti bundel.** Bila core dijalankan di Linux dan menemukan `git`/`python3`/`node` di PATH, registry melaporkannya dengan `source: "path"`. Itu kondisi host, bukan isi APK.
- **Kesiapan proyek:** `readiness: ready` berarti runtime terdeteksi tersedia dan dependensi proyek terpenuhi. Nilai `needs_runtime` dan `needs_dependencies` adalah sinyal jujur bahwa prasyarat jalan proyek belum terpenuhi di perangkat.
