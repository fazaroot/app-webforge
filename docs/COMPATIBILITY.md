# Kompatibilitas WebForge Mobile — v0.3.2

Matriks ini menyatakan status jujur setiap fitur dan runtime di v0.3.2 (`com.webforge.mobile`, Android `minSdk 26` / `targetSdk 35`, ARM64). v0.3.2 adalah rilis perbaikan engine berdasarkan hasil **Uji Semua Engine** nyata di POCO M6 pada 2026-11-26: static, PHP, Caddy, dan Apache lolos; Nginx, Python, Node.js, PostgreSQL, dan MariaDB gagal dengan error persis yang dicatat di matriks runtime. Perbaikan v0.3.2 menargetkan kelima kegagalan itu, tetapi status kelimanya tetap **Gagal di perangkat** sampai retest v0.3.2 di POCO M6 lolos. Status yang dipakai:

- **Berfungsi** — terimplementasi nyata dan terhubung ke core; perilaku sesuai keterangan.
- **Parsial** — sebagian berfungsi dengan batasan nyata yang dijelaskan; batasan tidak disembunyikan.
- **Terbuild di CI, menunggu tes perangkat** — binary benar-benar ada di APK hasil CI dan terdeteksi core, tetapi health check di POCO M6 belum lolos/terlapor. Status naik menjadi **Berfungsi** hanya setelah tes perangkat.
- **Gagal di perangkat** — self-test/health check di POCO M6 benar-benar gagal; error ringkasnya dicatat apa adanya. Perbaikan yang sudah dibuat tidak menaikkan status sebelum retest perangkat lolos.
- **Belum tersedia — belum dibundel** — tidak ada di APK. Aplikasi menampilkan status ini beserta alasannya dan tidak menyediakan tombol Start. Rencana bundelnya ada di [RUNTIME_PLAN.md](RUNTIME_PLAN.md).

Prinsip yang mengikat seluruh matriks: status server `running` hanya dari health check yang lolos, deteksi runtime hanya dari binary yang benar-benar ada, dan angka monitoring hanya dari `/proc` yang benar-benar terbaca. Tidak ada mock data di jalur produksi.

## Matriks fitur

| Fitur | Status v0.3.2 | Alasan / keterangan |
|---|---|---|
| Static server (Rust) | **Berfungsi** | Terbukti di POCO M6 (self-test 2026-11-26: marker terverifikasi via HTTP GET). Menyajikan file dari document root proyek. Di Android berjalan sebagai task in-process (`in_process: true`, `pid: null`); di host dev sebagai proses anak `webforge-core serve-static`. Start memeriksa konflik port lalu health check (TCP + HTTP GET `/` status < 500, maks. 5 detik); gagal berarti status `error`, bukan `running`. Bind `127.0.0.1` default, LAN opt-in per server. HTTP saja, port ≥ 1024. |
| Deteksi 17 framework | **Parsial** | Deteksi berbasis file berfungsi untuk 17 pola: Static HTML, Native PHP, Laravel, CodeIgniter 4, Symfony, WordPress, Flask, Django, FastAPI, Express, NestJS, Next.js, Nuxt, Vue, React, Angular, SvelteKit (plus `Unknown` sebagai fallback). Hasilnya mencakup bahasa, runtime yang direkomendasikan, document root yang disarankan, file penanda yang ditemukan, dan `readiness`. Parsial karena deteksi ≠ bisa jalan: proyek PHP/Python/Node terdeteksi dengan benar tetapi proyek tetap `readiness: needs_dependencies` bila dependensinya belum terinstal. Deteksi adalah heuristik file, bukan analisis kode penuh; versi framework hanya dilaporkan bila terbaca dari file penanda. |
| File manager | **Berfungsi** | List, baca (maks. 1 MB; biner ditolak `415`), tulis, mkdir, rename, copy, move, delete, pencarian nama rekursif (maks. 200 hasil), dan ukuran direktori — semua di dalam folder proyek. Path di-canonicalize; traversal keluar proyek ditolak `403`. Code editor (CodeMirror 6) memakai endpoint baca/tulis yang sama. Wilayah kerja adalah workspace aplikasi, bukan seluruh penyimpanan HP. |
| SQLite manager | **Berfungsi** | Database SQLite dibuat di `<data>/databases/<name>.db`; daftar tabel/kolom, query SELECT maupun DML (error SQL dikembalikan apa adanya), backup, dan restore dari folder backup. Ini manajer untuk file SQLite milik aplikasi — bukan server database jaringan. |
| Terminal | **Parsial** | Eksekusi `sh -c` nyata di cwd proyek/workspace, timeout 30 detik, streaming WebSocket, riwayat tersimpan. Parsial karena shell Android sangat terbatas: bukan bash, tidak ada manajer paket sistem; `pip`/`npm` tersedia lewat panel runtime Python/Node (bukan perintah terminal umum), dan binary yang bisa dipanggil hanya yang ada di sistem/`nativeLibraryDir`. |
| Monitoring | **Parsial** | CPU dari delta `/proc/stat` (2 sampel, 200 ms), memori dari `/proc/meminfo`, storage dari statvfs workspace, port LISTEN dari `/proc/net/tcp`+`tcp6` (state `0A`), riwayat tiap 30 detik. Parsial karena bergantung pada keterbacaan `/proc` di perangkat: bila tidak tersedia, nilai `null` + `unavailable_reason`, bukan angka karangan. Sebagian OEM membatasi visibilitas proses aplikasi lain, jadi daftar proses bisa lebih pendek dari kenyataan sistem. |
| Logs | **Berfungsi** | Log aplikasi dan per-server tersimpan di SQLite, bisa difilter severity/pencarian, dan diekspor sebagai teks. Log static server berasal dari proses/task yang benar-benar berjalan. |
| Diagnostics | **Berfungsi** | `GET /api/system/diagnostics` menjalankan pemeriksaan nyata (runtime terdeteksi, port, storage) dengan status `ok`/`warn`/`error` per pemeriksaan. Sejak v0.3.1 ada **Uji Semua Engine** (`POST /api/diagnostics/self-test`): tiap engine benar-benar di-start di port ephemeral dengan docroot temp, di-GET, lalu di-stop; PostgreSQL/MariaDB diuji dengan instance temp + `SELECT 1`. Panel Log Startup menampilkan kejadian startup core (hasil nativeStart, error library, progres ekstraksi aset, restart watchdog) agar kegagalan bisa dilaporkan dengan bukti. |
| Git status | **Parsial** | `git status --porcelain` nyata **bila** binary git terdeteksi di PATH/`nativeLibraryDir`. Di APK Android Phase 1 git tidak dibundel, jadi umumnya `available: false` dengan alasan. Di host dev yang punya git, fitur ini berfungsi penuh. |
| Background service | **Parsial** | Foreground service dengan notifikasi persisten menjaga core tetap hidup selama sistem mengizinkan; sejak v0.2.0 partial WakeLock dipegang selama ada server running (toggle di Pengaturan), watchdog me-restart core yang mati, dan ada jalan ke pengaturan baterai. Parsial karena Android tetap berhak menghentikan proses: optimasi baterai OEM, batas proses latar, dan phantom-process killer (Android 12+) bisa mematikan core beserta servernya. Tidak ada janji uptime. |
| SAF (impor folder) | **Parsial** | Pemilih folder `ACTION_OPEN_DOCUMENT_TREE` berfungsi dan menyalin tree terpilih ke workspace lewat `DocumentFile`, lalu proyek didaftarkan dari salinan itu. Parsial karena modelnya salin-masuk: folder asal tidak diedit langsung, perubahan tidak menulis balik, dan aplikasi tidak meminta `MANAGE_EXTERNAL_STORAGE`. Server membutuhkan path nyata, dan SAF tidak menyediakan path bebas — lihat [ARCHITECTURE.md](ARCHITECTURE.md). |

## Matriks runtime dan layanan

| Runtime / layanan | Status v0.3.2 | Alasan / keterangan |
|---|---|---|
| PHP | **Berfungsi** | Terbukti di POCO M6 (self-test 2026-11-26: PHP 8.3.14 lolos, marker terverifikasi via HTTP GET). PHP 8.3 CLI di-cross-compile di CI (NDK, dependensi statis) sebagai `libphp.so`; engine `php -S`, php.ini terkelola, PHP info, dan PHP CLI runner terhubung ke binary nyata itu. Composer belum dibundel; dependensi proyek diasumsikan sudah ada (`vendor/`). |
| PHP-FPM | **Belum tersedia — belum dibundel** | PHP CLI/`php -S` dibundel, tetapi SAPI FPM tidak dibangun. PHP di belakang Nginx/Caddy/Apache memakai backend `php -S` lewat proxy, bukan FPM. |
| Apache httpd | **Berfungsi** | Terbukti di POCO M6 (self-test 2026-11-26: Apache 2.4.62 lolos, marker terverifikasi via HTTP GET). httpd 2.4 di-cross-compile statis (APR, APR-util, PCRE2, expat, OpenSSL) sebagai `libhttpd.so`; core men-generate `httpd.conf` + VirtualHost per proyek, validasi `httpd -t` sebelum start. `mod_proxy` sengaja tidak dikompilasi: permintaan proxy untuk Apache mengembalikan error jujur. HTTP saja. |
| Nginx | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `"daemon" directive is duplicate` dan error log compile-time `/webforge/error.log` tidak bisa dibuka. Perbaikan v0.3.2: `daemon off;` hanya di konfigurasi (flag `-g` yang menggandakan dihapus) dan path bawaan Nginx dibuat relatif terhadap prefix runtime. Status naik hanya setelah retest v0.3.2 lolos. HTTP saja (tanpa SSL/HTTP2). |
| Caddy | **Berfungsi** | Terbukti di POCO M6 (self-test 2026-11-26: lolos, marker terverifikasi via HTTP GET). Caddy 2.8.4 di-cross-compile Go (`GOOS=android`, `GOARCH=arm64`, `CGO_ENABLED=0`) sebagai `libcaddy.so`; core men-generate Caddyfile (`file_server`, opsi `reverse_proxy`), validasi `caddy validate`. v0.3.2 menanam `CustomVersion=v2.8.4` agar `caddy version` tidak lagi menampilkan hash commit. TLS otomatis/ACME tidak dipakai untuk alamat lokal. |
| Python / Flask / Django / FastAPI | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `ModuleNotFoundError: No module named 'math'` saat import `http.server` (modul ekstensi inti tidak statis dan `lib-dynload` tidak dikemas). Perbaikan v0.3.2: semua modul ekstensi aktif dipaksa statis dan CI gagal keras bila modul kritis (termasuk `math`) tidak terdaftar di binary. Status naik hanya setelah retest v0.3.2 lolos. Framework tetap harus terinstal dari requirements proyek; wheel native Android umumnya tidak tersedia. |
| Node.js / npm | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `dlopen failed: library "libc++_shared.so" not found` untuk `libwebforge_node.so`. Perbaikan v0.3.2: `libc++_shared.so` dari NDK dikemas ke APK dan divalidasi CI. Status naik hanya setelah retest v0.3.2 lolos. Node berjalan di proses `:node` terpisah (stop membunuh proses itu); npm CLI dibundel (`npm.zip`); modul native `.node` umumnya tidak tersedia untuk Android. |
| MariaDB | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: bootstrap `ERROR: 1046 No database selected`. Perbaikan v0.3.2: SQL bootstrap diawali `CREATE DATABASE IF NOT EXISTS mysql; USE mysql;` dan password root dipasang untuk localhost + 127.0.0.1. Status naik hanya setelah retest v0.3.2 lolos. Koneksi MariaDB/MySQL eksternal tetap tersedia (tes koneksi TCP+auth nyata). Lisensi GPLv2 berlaku untuk binary MariaDB. |
| PostgreSQL | **Gagal di perangkat** | Self-test POCO M6 2026-11-26 gagal: `initdb: error: program "postgres" is needed by initdb but was not found in the same directory as ".../libinitdb.so"` (path executable di-realpath menembus symlink). Perbaikan v0.3.2: patch `normalize_exec_path` PostgreSQL agar lokasi symlink `bin/` dipertahankan, plus symlink basi antar update APK diganti otomatis. Status naik hanya setelah retest v0.3.2 lolos. Shared memory dipaksa `mmap`; tanpa ICU/XML (collation C/POSIX). |
| SSL / ACME (HTTPS) | **Belum tersedia — belum dibundel** | Semua server lokal melayani HTTP saja; Nginx dibangun tanpa modul SSL/HTTP2. Tabel `certificates` ada di skema sebagai registry, tetapi penerbitan/penyajian HTTPS belum diimplementasikan. ACME juga membutuhkan domain publik dan tantangan yang bisa dijangkau internet — tidak realistis dari HP di jaringan lokal tanpa tunnel. |

## Catatan perangkat dan platform

- **Arsitektur:** APK v0.3.2 menargetkan `arm64-v8a`. Perangkat uji utama adalah Xiaomi POCO M6 (ARM64, HyperOS); bukti perangkat terakhir adalah Uji Semua Engine 2026-11-26 pada v0.3.1 (static/PHP/Caddy/Apache lolos; Nginx/Python/Node/PostgreSQL/MariaDB gagal dan diperbaiki di v0.3.2 menunggu retest). Perilaku OEM lain — terutama soal pembunuhan proses latar — bisa berbeda dan belum terverifikasi di luar perangkat uji.
- **Versi Android:** `minSdk 26`, `targetSdk 35`. Kebijakan W^X Android 10+ berlaku penuh: kode native hanya dieksekusi dari `nativeLibraryDir`.
- **Port:** hanya port ≥ 1024. Management API tetap di `127.0.0.1:8765` dan tidak bisa diakses dari jaringan.
- **Deteksi di host dev bukan bukti bundel.** Bila core dijalankan di Linux dan menemukan `git`/`python3`/`node` di PATH, registry melaporkannya dengan `source: "path"`. Itu kondisi host, bukan isi APK.
- **Kesiapan proyek:** `readiness: ready` berarti runtime terdeteksi tersedia dan dependensi proyek terpenuhi. Nilai `needs_runtime` dan `needs_dependencies` adalah sinyal jujur bahwa prasyarat jalan proyek belum terpenuhi di perangkat.
